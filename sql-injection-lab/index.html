📚 什麼是 SQL Injection？

SQL Injection（SQL 注入）是最常見的 Web 應用程式弱點之一。當程式把使用者輸入直接拼接進 SQL 查詢字串時，攻擊者可以透過特製的輸入，改變這段 SQL 原本的語意，進而讀取、竄改甚至刪除資料。

核心問題：程式沒有把「資料」和「SQL 指令」分開。對資料庫而言，它分不出哪些是你要查的值、哪些是你偷塞的語法。

🔄 一次注入的基本流程

👤 使用者輸入→🌐 Web 應用程式→🧩 組出 SQL→⚙️ SQL 解析器→🗄️ 資料庫

弱點就發生在「組出 SQL」這一步：如果輸入被當成語法拼進去，後面解析器就會忠實執行被改寫過的指令。

✅ 一句話記住

把所有不可信的輸入都當成「資料」，永遠不要讓它變成「SQL 語法」。本實驗室所有防禦技巧，都是在實現這一個原則。

🧠 六種常見的 SQL Injection 教學型態

以下皆為概念說明，供課堂理解與防禦設計之用。

1

登入繞過 Login Bypass

在帳號/密碼欄位塞入會讓 WHERE 條件恆真，或用註解砍掉密碼比對的輸入，藉此略過驗證。

例：admin' -- 會讓查詢變成「找 admin，後面都註解掉」。

2

UNION-based

利用 UNION SELECT 把其他資料表的欄位併進原本的查詢結果，用來撈出額外資料。前提是欄位數量與型別要對得上。

3

布林盲注 Boolean Blind

當頁面不直接顯示資料，但在「條件成立 / 不成立」時回應不同，就能一位一位推測出內容。

4

時間盲注 Time-based Blind

連回應差異都看不到時，用讓資料庫延遲（如 SLEEP）當作訊號：有延遲代表條件成立。

5

ORDER BY 排序注入

排序欄位是 SQL 的「結構（識別字）」而非「值」，不能用參數綁定處理，必須改用白名單，否則容易成為注入點。

6

WAF 繞過

WAF 能攔截部分已知樣式，但攻擊者常以大小寫、編碼、註解拆字等方式變形繞過，所以它只能是輔助防線。

🔐 各語言的安全查詢寫法

共通原則：讓 SQL 結構固定、使用者輸入一律以參數帶入。

❌ 不安全（字串拼接）

sql = "SELECT * FROM users WHERE name = '" + username + "'"

✅ 安全（參數化）

sql = "SELECT * FROM users WHERE name = ?"
cursor.execute(sql, (username,))

重點：參數化把「語句結構」和「輸入資料」分開，輸入不會被當語法執行。

🐍 Python（sqlite3）

import sqlite3
conn = sqlite3.connect("app.db")
cur = conn.cursor()

username = request.form["username"]
cur.execute(
    "SELECT id, name FROM users WHERE username = ?",
    (username,),
)
rows = cur.fetchall()

🐍 Python（PostgreSQL / psycopg）

import psycopg
with psycopg.connect(DSN) as conn:
    with conn.cursor() as cur:
        cur.execute(
            "SELECT id, name FROM users WHERE username = %s",
            (username,),
        )
        rows = cur.fetchall()

🟢 Node.js（mysql2）

const mysql = require("mysql2/promise");
const conn = await mysql.createConnection(cfg);

const [rows] = await conn.execute(
  "SELECT id, name FROM users WHERE username = ?",
  [username]
);

🐘 PHP（PDO）

$pdo = new PDO($dsn, $user, $pass);
$stmt = $pdo->prepare(
  "SELECT id, name FROM users WHERE username = :u"
);
$stmt->execute([":u" => $username]);
$rows = $stmt->fetchAll();

☕ Java（JDBC PreparedStatement）

String sql =
  "SELECT id, name FROM users WHERE username = ?";
try (PreparedStatement ps =
        conn.prepareStatement(sql)) {
    ps.setString(1, username);
    ResultSet rs = ps.executeQuery();
}

⚠️ ORDER BY 為什麼要用白名單

// 欄位名是「結構」，不能用參數綁定
const ALLOWED = ["name", "email", "created_at"];
if (!ALLOWED.includes(sortBy)) {
  throw new Error("Invalid sort column");
}
const sql =
  `SELECT * FROM users ORDER BY ${sortBy}`;

值用參數化、識別字用白名單，兩者分工。

🛡️ 多層防禦（縱深防禦）

輸入驗證→參數化查詢→最小權限→一般化錯誤處理→記錄 / 告警 + WAF
① 參數化查詢
最核心：資料與 SQL 結構分離。
② 輸入驗證
確認格式/型別/範圍符合預期。
③ 最小權限
資料庫帳號只給必要權限。
④ 錯誤處理
不把資料庫細節回傳給使用者。
⑤ 記錄與告警
留下日誌、異常時示警。
⑥ WAF
額外防線，不能取代上述。
