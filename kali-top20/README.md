## 1. Nmap — 網路偵察與連接埠掃描

- **用途**：攻擊者在行動初期用來盤點「有哪些主機活著、開了哪些服務、可能是什麼作業系統與版本」，據此規劃後續目標。
- **運作原理（概念）**：對目標送出各種探測封包，依回應判斷連接埠狀態（開放/關閉/被過濾）與服務指紋。它是「畫地圖」的動作，本身不入侵，但決定了攻擊面。
- **常見跡象**：短時間內單一來源對大量連接埠或大量主機發出連線；非業務時段的掃描；SYN 掃描造成的半開連線；防火牆/IDS 的掃描告警。
- **防治措施**：
  - 落實**網路分段**與最小暴露面，只開放必要服務。
  - 在邊界與內網部署 **IDS/IPS（Suricata/Snort）** 偵測掃描特徵並限速。
  - 關閉/隱藏不必要的服務橫幅（banner），定期自行掃描盤點（以攻制守）。

## 2. Hydra / Medusa — 線上帳密暴力破解

- **用途**：針對登入服務（SSH、RDP、FTP、HTTP 表單等）嘗試大量帳密組合，直到猜中。
- **運作原理（概念）**：以字典或規則產生大量帳密，自動化地逐一送出登入請求，依「成功/失敗」回應判斷是否命中。
- **常見跡象**：同一帳號或同一來源在短時間內大量登入失敗；來自異常地理位置的嘗試；多個帳號被同一 IP 輪流嘗試。
- **防治措施**：
  - **帳戶鎖定 / 漸進式延遲 / 限流**，讓暴力破解在時間成本上不可行。
  - 全面導入 **MFA（多因素驗證）**。
  - 限制管理服務對外暴露（VPN / 允許清單），監控並封鎖異常來源。

## 3. John the Ripper / Hashcat — 離線密碼破解

- **用途**：當攻擊者已取得密碼**雜湊檔**，在自己機器上離線還原出明文。
- **運作原理（概念）**：用字典、規則變形或暴力法產生候選密碼，計算其雜湊與目標比對。GPU 讓每秒可嘗試的數量極高，弱雜湊（無鹽 MD5/SHA1）幾乎瞬破。
- **常見跡象**：此步驟多在攻擊者端離線進行，**難以直接偵測**；重點放在「雜湊檔外洩」這個前置事件（異常讀取 /etc/shadow、SAM、資料庫 dump）。
- **防治措施**：
  - 使用**慢雜湊且加鹽**（bcrypt、scrypt、Argon2），淘汰 MD5/SHA1。
  - 強制**長且高熵的密碼/通關密語**，鼓勵密碼管理器。
  - 嚴格保護雜湊存放處，監控對憑證檔的異常存取。

## 4. Aircrack-ng — Wi‑Fi（WPA/WPA2）破解

- **用途**：針對無線網路，嘗試還原 WPA/WPA2 預共享金鑰（PSK）。
- **運作原理（概念）**：擷取裝置連線時的交握（handshake）封包，再**離線**用字典比對推算金鑰；弱 PSK 容易被猜中。
- **常見跡象**：出現未知的監聽介面或大量去認證（deauth）封包；使用者頻繁被踢下線；附近出現異常探測。
- **防治措施**：
  - 採用 **WPA3**（或至少 WPA2 + 高強度隨機 PSK，長度足夠）。
  - 企業環境改用 **WPA2/3-Enterprise（802.1X）** 搭配個別帳號。
  - 啟用管理框架保護（PMF/802.11w），監控流氓 AP 與 deauth 攻擊。

## 5. Wireshark — 封包嗅探與流量分析

- **用途**：擷取並分析網路流量，攻擊者用來找明文憑證或敏感資料；藍隊也用它做鑑識。
- **運作原理（概念）**：把網卡設為可接收流量並解析各層協定。若流量未加密，內容（含帳密）一覽無遺。
- **常見跡象**：介面進入混雜模式；在交換式網路中出現搭配 ARP 欺騙才能嗅探的情形（見第 6 項）。
- **防治措施**：
  - **全程加密**（TLS、SSH、VPN），淘汰明文協定（Telnet、FTP、HTTP）。
  - 使用交換式網路、**802.1X 埠認證**，限制可接取點。
  - 對敏感網段做監控，偵測異常的大量鏡像/嗅探行為。

## 6. Ettercap / Bettercap — 中間人攻擊與 ARP 欺騙

- **用途**：讓攻擊者插入到兩方通訊之間，竊聽或竄改流量。
- **運作原理（概念）**：以偽造的 ARP 回應讓受害者把攻擊者當成閘道（ARP 欺騙），流量於是繞經攻擊者；再搭配嗅探或降級攻擊取得資料。
- **常見跡象**：ARP 表中同一 IP 對應到多個/變動的 MAC；閘道 MAC 突然改變；大量 ARP 回應。
- **防治措施**：
  - 交換器啟用 **Dynamic ARP Inspection（DAI）+ DHCP Snooping**。
  - 對重要主機設**靜態 ARP**；全站強制 **HTTPS + HSTS**，必要服務用憑證釘選。
  - 網路分段，縮小單一廣播域的受害範圍。

## 7. Metasploit Framework — 漏洞利用與後滲透框架

- **用途**：整合已知漏洞的利用模組、載荷（payload）與後滲透工具，是最常見的滲透測試框架。
- **運作原理（概念）**：對有已知弱點的服務投遞對應的利用模組，取得執行權或連線（如 Meterpreter），再進行後續操作。核心前提是「目標存在未修補的弱點」。
- **常見跡象**：已知 exploit 的網路特徵；可疑的反向連線（callback）；異常新進程/服務；EDR 對常見載荷的告警。
- **防治措施**：
  - **及時修補**，建立弱點管理流程（優先處理可被遠端利用者）。
  - 部署 **EDR/AV** 偵測常見載荷，網路出口限制可疑的 C2 連線。
  - 最小權限與應用白名單，降低利用成功後的影響。

## 8. SQLmap — 自動化 SQL 注入

- **用途**：自動偵測並利用 Web 應用的 SQL 注入弱點，撈取資料庫內容。
- **運作原理（概念）**：對輸入點自動送出各種探測，依回應差異/延遲判斷是否可注入，再自動化地抽取資料。它把人工注入流程自動化。
- **常見跡象**：參數中出現大量含 SQL 關鍵字、註解符號、布林/時間測試的請求；單一來源對同一端點高頻試探；WAF 告警。
- **防治措施**：
  - **參數化查詢 / Prepared Statement**（根本防禦），識別字用白名單。
  - 資料庫帳號**最小權限**、一般化錯誤訊息，避免資訊洩漏。
  - WAF 作為輔助防線，搭配日誌與告警（可參閱本專案的 `sql-injection-lab`）。

## 9. Burp Suite — Web 攔截代理與測試平台

- **用途**：攔截、檢視、修改瀏覽器與伺服器之間的 HTTP(S) 請求，是 Web 滲透測試的主力工具。
- **運作原理（概念）**：作為中間代理，讓測試者能改掉「前端看似鎖定」的參數、重放請求、模糊測試，藉此找出伺服器端驗證不足的弱點。
- **常見跡象**：同一端點出現被竄改的參數、異常的重放與高頻模糊測試；不符合正常前端流程的請求序列。
- **防治措施**：
  - **永遠在伺服器端重新驗證**授權與輸入，絕不信任前端送來的值。
  - 對敏感操作做權限檢查、速率限制與異常行為監控。
  - 實作 CSRF/授權等防護，記錄並告警異常請求樣式。

## 10. Nikto — Web 伺服器弱點掃描

- **用途**：快速掃描 Web 伺服器的已知問題，如危險檔案、過時版本、錯誤設定。
- **運作原理（概念）**：對伺服器比對一份已知問題清單，逐一請求並檢查回應。屬於「盤點已知弱點」的偵察動作。
- **常見跡象**：短時間大量請求各種已知路徑/檔名；User-Agent 具掃描器特徵；大量 404/403。
- **防治措施**：
  - 移除**預設檔案、範例與後台**，關閉不必要模組。
  - 持續修補並隱藏版本橫幅；以 WAF/速率限制削弱自動掃描。
  - 定期自掃，把自己的伺服器維持在已知無弱點狀態。

## 11. Gobuster / dirb / feroxbuster — 目錄與檔案列舉

- **用途**：以字典猜測網站上「沒有被連結、但確實存在」的目錄或檔案（備份、後台、API）。
- **運作原理（概念）**：對大量候選路徑發出請求，依狀態碼/回應大小判斷哪些存在。
- **常見跡象**：單一來源在短時間產生大量 404、規律字典式路徑請求。
- **防治措施**：
  - **關閉目錄列出（directory listing）**，不要把備份/機密檔放在網站根目錄。
  - 讓不存在與禁止存取的回應**一致化**（避免用回應差異洩漏存在性）。
  - 速率限制與監控異常列舉行為。

## 12. Responder — LLMNR / NBT-NS 毒化

- **用途**：在內網（尤其 Windows 環境）誘騙主機送出認證，藉以擷取挑戰雜湊。
- **運作原理（概念）**：當主機找不到名稱解析時會廣播求助，Responder 冒充回應，使受害者向攻擊者認證，進而取得可離線破解或轉送的雜湊。
- **常見跡象**：內網出現對 LLMNR/NBT-NS 廣播的異常回應；非預期主機回應名稱查詢。
- **防治措施**：
  - **停用 LLMNR 與 NBT-NS**，改用正確的 DNS。
  - 啟用 **SMB 簽章**，降低 relay 風險；導入 MFA 與分層管理。
  - 監控內網廣播回應異常。

## 13. CrackMapExec / SMB — 內網橫向移動

- **用途**：在取得一組憑證後，快速驗證它能登入哪些主機、並在內網橫向擴展。
- **運作原理（概念）**：用同一組帳密對大量主機測試 SMB/WinRM 等登入，找出可用之處；常與雜湊傳遞（pass-the-hash）等概念結合。
- **常見跡象**：同一帳號在短時間登入大量主機；異常的 SMB/WinRM 連線；本機管理員帳號被重複使用。
- **防治措施**：
  - 禁止**本機管理員密碼重用**，導入 **LAPS**（每台獨立隨機密碼）。
  - 網路分段、限制管理協定、**分層式管理帳號（tiering）**。
  - 監控異常橫向登入行為，啟用 SMB 簽章。

## 14. 憑證擷取（Mimikatz 類情境）

- **用途**：在已取得主機高權限後，從記憶體或系統中抽取登入憑證/票證，用以擴大控制。
- **運作原理（概念）**：利用系統保存登入憑證的機制，抽出明文、雜湊或 Kerberos 票證，再拿去登入其他系統。**前提是攻擊者已握有本機高權限**。
- **常見跡象**：對 LSASS 等憑證處理程序的異常存取；異常票證請求；EDR 針對憑證擷取行為的告警。
- **防治措施**：
  - 啟用 **Credential Guard / 受保護的 LSASS**，更新作業系統。
  - 限制特權帳號登入一般工作站（避免高權憑證落地），縮短票證效期。
  - 部署 EDR 偵測憑證存取行為，落實最小權限。

## 15. 社交工程 / 釣魚（SET 類工具情境）

- **用途**：不打系統、改打「人」——以假冒郵件、網站或訊息誘使使用者交出帳密或執行惡意檔案。
- **運作原理（概念）**：製造信任或急迫感（冒充 IT、主管、廠商），引導受害者點連結、輸入憑證或開啟附件。這是最常見的初始入口。
- **常見跡象**：寄件網域相近但不符、連結導向假登入頁、不尋常的急迫語氣與附件；回報的可疑郵件增加。
- **防治措施**：
  - 持續性**使用者資安意識教育**與演練（模擬釣魚）。
  - 郵件防護（SPF/DKIM/DMARC、附件沙箱、連結改寫）、全面 **MFA**。
  - 建立**容易回報**的通報管道與快速處置流程。

## 16. DNS 欺騙 / 快取毒化

- **用途**：把使用者導向攻擊者控制的伺服器（假網站、憑證竊取、惡意下載）。
- **運作原理（概念）**：偽造 DNS 回應或污染解析快取，使網域名稱被解析到錯誤 IP。常與中間人位置搭配。
- **常見跡象**：同一網域解析結果異常改變；使用者被導向可疑站點；DNS 回應來源異常。
- **防治措施**：
  - 部署 **DNSSEC**，使用可信且加密的解析器（DoH/DoT）。
  - 固定/鎖定內部 DNS 設定，防止被竄改；配合 HTTPS/HSTS 降低影響。
  - 監控 DNS 解析異常與可疑網域查詢。

## 17. 密碼噴灑（Password Spraying）

- **用途**：用**少數幾個常見密碼**去試**大量帳號**，以避開「單一帳號多次失敗」的鎖定機制。
- **運作原理（概念）**：橫向鋪開：每個帳號只試一兩個熱門密碼，再換下一個帳號，整體命中率仍可觀，卻不易觸發傳統鎖定。
- **常見跡象**：**大量不同帳號**各出現少量失敗、且時間/來源相近；跨帳號的規律嘗試。
- **防治措施**：
  - **MFA** 是最有效的緩解。
  - 採用**以來源/行為為基礎的智慧鎖定與偵測**（而非只看單帳號失敗次數）。
  - 禁用常見弱密碼（密碼黑名單），監控跨帳號失敗樣式。

## 18. Wifite — 自動化無線攻擊

- **用途**：把多種無線攻擊（擷取交握、WPS、去認證等）自動化、一鍵對周遭網路發動。
- **運作原理（概念）**：自動掃描周遭 AP，依弱點挑選對應手法（如弱 WPS PIN、弱 PSK）嘗試取得金鑰。降低了攻擊門檻。
- **常見跡象**：大量 deauth 封包、對 WPS 的連續嘗試、附近出現監聽裝置。
- **防治措施**：
  - **關閉 WPS**，改用 WPA3 或高強度隨機 PSK。
  - 啟用管理框架保護（802.11w），監控 deauth 與流氓 AP。
  - 企業級 802.1X 認證，定期巡檢無線環境。

## 19. 隱寫術與憑證收集（資料外洩/持久化情境）

- **用途**：攻擊者把竊得資料藏進看似無害的檔案（圖片、文件）以躲避偵測，或在環境中蒐集散落的憑證。
- **運作原理（概念）**：隱寫術把資料嵌入媒體檔的冗餘位元，使外洩流量看似正常；憑證收集則掃描設定檔、腳本、歷史紀錄中殘留的帳密與金鑰。
- **常見跡象**：異常大的媒體檔外送、出口流量異常；對設定檔/金鑰檔的大範圍讀取；非預期的壓縮/編碼行為。
- **防治措施**：
  - 部署 **DLP** 與**出口流量監控**，對異常外送告警。
  - 不要把密碼/金鑰寫死在檔案或程式碼中，改用秘密管理（vault）。
  - 檔案完整性監控與定期掃描殘留憑證。

## 20. 權限提升（Privilege Escalation）

- **用途**：從低權限立足點提升到更高權限（本機 root/SYSTEM，或網域層級），以完全掌控系統。
- **運作原理（概念）**：利用設定錯誤（過寬權限、可寫服務、sudo 設定不當）、未修補的本機漏洞，或憑證重用，把權限一步步往上抬。
- **常見跡象**：異常的 sudo/提權呼叫、可疑的新服務或排程、對敏感設定的修改、EDR 的提權告警。
- **防治措施**：
  - **及時修補**本機漏洞，建立並稽核**設定基準線**（CIS Benchmark）。
  - 嚴守**最小權限**，謹慎設定 sudo/服務權限、檔案 ACL。
  - 部署 EDR 偵測提權行為，分層管理特權帳號。
